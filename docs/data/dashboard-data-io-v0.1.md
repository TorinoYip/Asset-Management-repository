# Asset Intellgent 看板数据 I/O 与数据源属性清单（v0.1）

> 状态：对齐草案  
> 基线：当前 `apps/web` 五页看板；第 5 页“蒙西日报”仅保留入口，不纳入本轮月度数据模型  
> 最小时间粒度：月度  
> 详细字段：见 [`dashboard-source-field-inventory-v0.1.csv`](dashboard-source-field-inventory-v0.1.csv)

## 1. 本版结论

当前网页已经验证了页面结构和筛选逻辑，但 `apps/web/src/data/portfolio.js` 仍是原型数据容器，不是可直接对接生产数据的数据接口：

- 资产主数据、财务数据、运营数据、状态和结算数据混在同一个前端文件；
- 组合、站点、风电单机、储能单站等不同粒度并存；
- 月度趋势目前只有资产类型级数组，没有完整的 `年月 × 电站/资产` 主键；
- 部分目标、站点金额、运营 KPI 和月份对比由前端比例推算；
- 经纬度、状态阈值、更新时间和数据质量标记尚未形成正式字段；
- 结算拆解目前按资产类型固定，不随省份、电站和月份完整变化。

正式接入时，前端只应接收标准化结果，不再承担金额分摊、目标反推和运营指标估算。

## 2. 看板数据 I/O 边界

```text
页面输入
统计月 / 省份 / 电站 / 资产类型 / 时间尺度 / 指标 / 对比月
        │
        ▼
统一查询上下文
as_of_month + province_id + station_id + asset_type
        │
        ├── 资产与地理主数据
        ├── 月度经营实际
        ├── 月度及年度目标
        ├── 风电场 / 风机月度运营
        ├── 储能单站月度运营
        ├── 资产状态与运维摘要
        └── 月度结算明细
        │
        ▼
语义层加工
YTD累计 / 目标达成 / 全年进度 / 组合聚合 / 排名 / 状态
        │
        ▼
页面输出
资产总览 / 营收总览 / 按类型分析 / 按站点分析
```

### 2.1 输入参数

| 参数 | 类型 | 必填 | 作用范围 | 说明 |
|---|---|---:|---|---|
| `as_of_month` | `YYYY-MM` | 是 | 全局 | 截至月份；月度看板的时间锚点 |
| `province_id` | string / `all` | 否 | 全局 | 省份，不再使用“区域”作为页面筛选层 |
| `station_id` | string / `all` | 否 | 第 2—5 页全局；首页表格局部 | 必须从当前省份与资产类型的有效电站中选择 |
| `asset_type` | enum | 是 | 全局 | `wind` / `storage` / `distributed` |
| `period_mode` | enum | 否 | 按类型分析 | `ytd` 或具体月份 |
| `metric_code` | string | 否 | 经营、运营比较 | 例如 `gross_margin`、`availability_rate` |
| `compare_month` | `YYYY-MM` | 否 | 营收总览 | 必须早于或等于 `as_of_month` |
| `table_province_id` | string / `all` | 否 | 首页资产构成与资产明细 | 局部筛选，不改变首页上方 KPI 和地图 |
| `table_station_id` | string / `all` | 否 | 首页资产构成与资产明细 | 与 `table_province_id` 联动 |

### 2.2 通用输出元数据

每个页面结果均应返回：

| 字段 | 说明 |
|---|---|
| `as_of_month` | 本次结果的统计截止月 |
| `scope` | 实际生效的省份、电站和资产类型 |
| `data_updated_at` | 本批看板数据完成更新时间 |
| `data_completeness_pct` | 当前范围内必填数据完整度 |
| `source_batch_id` | 可追溯到数据装载批次 |
| `warnings[]` | 缺月、未结算、目标缺失、不可计算等提示 |
| `currency` | 默认 `CNY` |
| `amount_display_unit` | 页面显示可用“亿元/万元”，底层统一保存“元” |

## 4. 建议的标准数据实体

### 4.1 主数据与规则

| 实体 | 主键 / 粒度 | 主要来源 | 用途 |
|---|---|---|---|
| `dim_province` | `province_id` | 资产台账 / GIS | 省份筛选和地图聚合 |
| `dim_station` | `station_id` | 资产台账 / EAM | 风电场、储能电站及分布式项目主数据 |
| `dim_asset` | `asset_id` | EAM / SCADA 设备台账 | 风电为单机；储能为单站，与风电单机保持同级分析能力 |
| `dim_metric` | `metric_code` | 指标字典 | 单位、方向、聚合规则、公式和阈值 |
| `dim_finance_item` | `finance_item_code` | 财务科目映射 | 统一风电/储能不同收入与成本分项 |
| `dim_calendar_month` | `stat_month` | 日历维表 | YTD、月份对比和缺月检查 |
| `rule_status_threshold` | 指标 × 资产类型 × 生效版本 | 业务规则表 | 将实际/目标差距转换为正常、关注、异常 |

### 4.2 月度事实

| 实体 | 唯一粒度 | 主要来源 | 刷新建议 |
|---|---|---|---|
| `fact_finance_monthly` | 电站 × 月 × 财务科目 × 版本 | ERP / 财务月报 | 月结后；允许重述版本 |
| `fact_target_monthly` | 范围对象 × 月 × 指标 × 目标版本 | 预算系统 / 年度目标表 | 年度下达及调整时 |
| `fact_wind_station_monthly` | 风电场 × 月 | SCADA / 电量系统 | 月度汇总 |
| `fact_wind_turbine_monthly` | 风机 × 月 | SCADA / 生产报表 | 月度汇总 |
| `fact_storage_station_monthly` | 储能单站 × 月 | EMS / 计量 / 交易系统 | 月度汇总 |
| `fact_asset_status_monthly` | 单机或单站 × 月 | EAM / 运营规则 | 月末快照 |
| `fact_maintenance_monthly` | 单机或单站 × 月 | CMMS / EAM | 月度汇总 |
| `fact_settlement_monthly` | 电站 × 月 × 结算科目 × 单据 | 结算台账 / ERP | 结算单到达后 |
| `data_load_audit` | 数据集 × 批次 | 数据平台 | 每次装载 |

## 5. 全量数据源登记

| 数据域 | 候选权威来源 | 当前原型对应 | 数据责任待确认 | 核心质量检查 |
|---|---|---|---|---|
| 省份、电站、设备主数据 | 资产台账 / EAM / GIS | `provinceMeta`、`stationRecords` | 资产管理 | ID 唯一；省站关系有效；容量单位一致；经纬度合法 |
| 财务实际 | ERP / 财务月报 | `stationRecords`、`businessData` | 财务 | 收入−成本=毛利；分项合计=总额；关账/重述版本清晰 |
| 年度及累计目标 | 预算系统 / 经批准目标表 | `businessData.target/annual/targetMonthly` | 财务规划/经营管理 | 月度目标合计=全年目标；累计目标单调且版本可追溯 |
| 风电生产运营 | SCADA / 电量计量 / 生产月报 | `operationsData.wind`、`ops` 文本 | 生产运营 | 单机汇总可对账到风电场；比例按分母加权；缺测不补零 |
| 储能生产运营 | EMS / 计量 / 交易月报 | `operationsData.storage`、`ops` 文本 | 储能运营 | 放电量不高于口径允许值；效率分母非零；MW/MWh 分离 |
| 资产状态 | EAM 状态 + 指标阈值 | `status` | 资产管理/运营 | 源状态与计算状态分列；无数据不能标正常 |
| 运维摘要 | CMMS / EAM | `maintenance` | 运维 | 故障数、修复数和 MTTR 可复算；计划/非计划分类一致 |
| 结算明细 | 结算台账 / ERP | `settlementData` | 财务/交易 | 单据唯一；本月与 YTD 可对账；未结算月明确标识 |
| 数据更新与质量 | 数据平台调度 | 页面固定“08:30” | 数据平台 | 批次、更新时间、完整度、警告均来自实际装载 |

## 6. 核心计算口径

底层金额统一保存为人民币元，比例统一保存为小数或百分数中的一种；不可在不同来源中混用。

| 指标 | 标准公式 | 聚合要求 |
|---|---|---|
| 实际 YTD | `Σ monthly_actual(同年1月..截至月)` | 缺月应返回警告，不能自动补 0 |
| 累计目标 | `Σ monthly_target(同年1月..截至月)` | 若源系统直接提供累计目标，需与月度目标和校验 |
| 全年目标 | `Σ monthly_target(同年1月..12月)` 或批准年度值 | 保存目标版本 |
| 毛利 | `总收入 - 总成本` | 允许与财务已发布毛利对账并保留差异 |
| YTD 差距 | `actual_ytd - cumulative_target` | 成本类的展示方向相反 |
| 累计目标达成率 | `actual_ytd / cumulative_target` | 分母为 0 时返回 `null`，不是 0% |
| 全年完成进度 | `actual_ytd / annual_target` | 不等同于累计目标达成率 |
| 组合比例 KPI | `Σ numerator / Σ denominator` | 禁止直接平均单站百分比 |
| MTTR | `修复总时长 / 已修复故障数` | 已修复故障数为 0 时返回 `null` |
| 储能效率 | `放电量 / 充电量` | 充电量为 0 时返回 `null` |
| 状态 | 按指标方向、阈值和数据质量综合计算 | `no_data` 与 `good` 分离 |

## 7. 当前代码到正式数据的映射与风险

| 当前对象/逻辑 | 现状 | 正式替代 | 风险级别 |
|---|---|---|---|
| `stationRecords` | 一行同时放主数据、YTD 财务、运营文本和状态 | `dim_station` + 月度事实表 | 高 |
| `businessData.monthly[]` | 只有资产类型级 1—7 月数组 | `fact_finance_monthly`，带年月和电站主键 | 高 |
| `financialRecord()` | 按组合总额比例缩放站点收入、成本和毛利 | 直接读取站点月度实际与目标 | 高 |
| 站点目标 | 通过 `margin / attainment` 反推 | `fact_target_monthly` | 高 |
| 收入/成本目标 | 通过固定 1.8%、6.9% 等比例反推 | 财务目标事实 | 高 |
| 月份对比 | 由毛利乘固定倍数模拟收入，再倒算成本 | 读取对应月份实际 | 高 |
| `record.ops` | “可利用率 98.1%”等文本 | 数值型专业事实字段 + `metric_code` | 高 |
| `operationsData.comparison` | 与站点记录分离的固定比较数组 | 风机/储能站月度事实 | 高 |
| `status` | 原型预先写死 | 源状态 + 规则计算状态 | 中 |
| 地图点位置 | 页面样式位置，不是经纬度投影 | `longitude` / `latitude` + 地图投影 | 中 |
| `settlementData` | 按资产类型固定行 | 电站 × 月 × 科目 × 单据 | 高 |
| “数据更新于 08:30” | 固定文案 | `data_load_audit.completed_at` | 中 |

## 8. 建议的页面接口形态

无需现在锁定 REST 或 GraphQL，但输出建议统一为“上下文 + 元数据 + 页面数据”：

```json
{
  "context": {
    "as_of_month": "2025-07",
    "province_id": "all",
    "station_id": "all",
    "asset_type": "wind"
  },
  "meta": {
    "data_updated_at": "2025-08-01T08:30:00+08:00",
    "source_batch_id": "monthly-2025-07-v2",
    "data_completeness_pct": 98.7,
    "warnings": []
  },
  "data": {
    "summary": {},
    "series": [],
    "rows": []
  }
}
```

建议页面级输出：

- `dashboard_overview(context)`
- `dashboard_business(context, metric_code, compare_month)`
- `dashboard_type_comparison(context, period_mode)`
- `dashboard_station(context, metric_code)`
- `dashboard_filter_options(context)`

筛选选项也必须由数据服务返回，不能继续在 HTML 中固定写死省份、电站和月份。

## 9. 下一轮数据对齐顺序

1. 先确认 `station_id`、`asset_id`、`stat_month` 三组主键及省份—电站—资产关系；
2. 对齐财务实际、累计目标、全年目标以及目标版本；
3. 对齐风电单机与储能单站的月度运营字段及分子/分母；
4. 对齐状态阈值、源状态和数据缺失状态；
5. 对齐经纬度、更新时间、批次和数据质量字段；
6. 最后接结算分项与运维摘要。

在第 1—3 步完成前，不建议把当前前端推算逻辑视为正式计算口径。
